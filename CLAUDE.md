# Project notes for the agent

- This is a Vite + React static site deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`. It serves at `https://<domain>/<repo-name>/`.
- `package.json` "name" must equal the GitHub repo name. `vite.config.js` derives the `base` path from it.
- `site.config.js` holds the domain, title, description, and OG copy. `scripts/prerender.mjs` reads it at build time and writes the meta tags, JSON-LD, sitemap, and the index-site embed script tags into `dist/index.html`, plus one prerendered page per current FBS team at `dist/team/<id>/index.html` with its own OG image.
- `npm run build` is `vite build` plus the prerender, which also mines every team's crowns and writes `dist/crowns/<id>.json` (a team page embeds its own; the dev server has no files and mines in the page instead). The deployed HTML contains the rendered page, so `src/main.jsx` uses `hydrateRoot`, and nothing may read `window` during render. Apply URL state in a `useEffect` after mount. The only path-derived state is the open team (`/team/<id>/`), passed in as the `initial` prop.
- Shareable state goes in the URL with one `replaceState` per change: `src/lib/url.ts` parses and builds it (pure, tested), `writeUrl` in `src/urlState.js` writes it. Params `c` (chips), `dir=L|U|C|N`, `scope=active` (default is all-time), `week=1`, `run`. The view's state and its rules (a new definition resets the column limit, presets switch to active) are the reducer in `src/lib/view.ts`. The analytics embed counts each `replaceState` as a pageview.
- Code layout: `src/lib` is TypeScript (`npm run typecheck`); components are still JSX. `createModel(payload)` in `createModel.ts` decodes a payload into per-team game rows and evaluates definitions; `model.ts` builds the app's one model from `src/data/payload.json`. The chip catalog is `chips.ts` and reads only row fields. `schema.ts` holds the payload's sentinels and flag bits, and the build scripts import it directly (Node strips the types). Tests are Vitest (`npm test`), next to the code.
- Analytics: `track()` in `src/lib/analytics.ts` wraps `window.dhAnalytics?.track(name, props)`, optional-chained because the embed is third-party and blockable. Events: definition, preset, team open, show more, share, save/unsave/apply saved streak, lead apply, leads scope, leads dir, week filter.
- Hover interactions use `onPointer*` events, not `onMouse*`, so they work on touch.
- Team marks are committed under `public/logos/` (one-color, result squares) and `public/logos-color/` (column heads, next-game chips, the ledger), one pair per ESPN id, fetched by `scripts/gen-logos.mjs`. `build-current.mjs` nulls the ESPN id of a team whose marks aren't committed (the chip shows its initial) and lists it in `data/build/logo-wants.json`; run `gen-logos`, then `build-current` again, when it reports new opponents. Color marks use ESPN's dark-background variant when it measurably reads better on the page (rule and the by-eye exceptions are in `gen-logos.mjs`); delete a file to refetch it.
- Favicon and OG images are generated by `npm run gen:favicon` and `npm run gen:og` on a developer machine and committed. CI does not regenerate them. `gen:og` writes `public/og.png`, `public/card.png` and 136 team cards under `public/og/team/`, drawing the real default board from the payload, so re-run it after a redesign, after any grid rule change (it mirrors the column layout, including the reserved top slot on a live run), and whenever a fresher board is worth committing. Text is drawn as opentype.js glyph outlines: sharp's librsvg ignores `FONTCONFIG_FILE`, and opentype.js 2.x emits NaN path data, so it is pinned to 1.3.4.
- Social crawlers fetch the exact URL's HTML without JS and GitHub Pages ignores query strings, so only the root and the team pages get their own preview. Per-definition previews need a proxy that rewrites `<head>` (Cloudflare worker plan in the spec); not built.
- Dev server: `npm run dev`. If port 5173 is busy, `npm run dev -- --port 5174`.
- Worktrees: `data/raw/` and `data/build/` live only in the main checkout. Symlink both into the worktree to run the pipeline, and never `git add -A` there, because the symlinks are not covered by the `.gitignore` directory patterns.
- The window starts at `FIRST_SEASON` in `scripts/lib/window.mjs` (1936). Before 1978 Howell's pages are the only game source; `fbs-span-bridges.json` and `extra-games.json` hold the researched wartime seasons, each row with a source and quote.
- Data rulings live in `data/ref/` and are applied at build time with fail-loud checks: `repole-errata.json` (parse-repole fails on an entry that matches no row), `coach-overrides.json` (build-payload must report 0 unresolved coach seasons), `alt-home.json`. After changing the errata, run `scripts/data/export-errata.mjs` against a checkout of `DrewHoo/repole-errata` and push it; that repo is the public CC0 copy.
- The `dataviz-pages-site` skill covers everything else: build-time data, researched datasets, mobile, dates, SEO, registering the project card on the index site.
