# Project notes for the agent

- This is a Vite + React static site deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`. It serves at `https://<domain>/<repo-name>/`.
- `package.json` "name" must equal the GitHub repo name. `vite.config.js` derives the `base` path from it.
- `site.config.js` holds the domain, title, description, and OG copy. `scripts/prerender.mjs` reads it at build time and writes the meta tags, JSON-LD, sitemap, and the index-site embed script tags into `dist/index.html`, plus one prerendered page per current FBS team at `dist/team/<id>/index.html` with its own OG image.
- `npm run build` is `vite build` plus the prerender, which also mines every team's crowns and writes `dist/crowns/<id>.json` (a team page embeds its own; the dev server has no files and mines in the page instead). The deployed HTML contains the rendered page, so `src/main.jsx` uses `hydrateRoot`, and nothing may read `window` during render. Apply URL state in a `useEffect` after mount. The only path-derived state is the team page (`/team/<id>/`), passed in as `initial.page`.
- `/games/` (the calendar button on the board) is the schedule: every scheduled game by week, with the line and the streak most on the line in it; a row opens its matchup. `scheduledGames()` in `team.ts` builds it. Above the weeks sits the broken-streaks digest (`broken.ts`): the runs a completed week's results ended, the week a picker. `/games/` shows the latest completed week; `/games/week/<n>/` is one week's own address, prerendered with its own OG image so a shared week keeps its preview.
- Three things open, one view each: a streak opens the board's panel (`?t=<id>`), a game opens the matchup sheet (`/team/<id>/?vs=<opp id>|next`, over whatever is showing), a team opens its page (`/team/<id>/`, in place of the board; its name is a picker for any other team). An old `/team/<id>/` link that carries a definition still opens the panel.
- Shareable state goes in the URL, one write per change: `src/lib/url.ts` parses and builds it (pure, tested), `writeUrl` in `src/urlState.js` writes it. A definition change is a `replaceState`; opening a panel or a matchup, or moving between the board and a team page, is a `pushState` that records the URL underneath, so the close button steps back when Back would land on the same thing (`close()` in `App.jsx`). Params `c` (chips), `dir=L|U|C|N` or `dir=W10|L7` (won or lost by at least that margin, every game; `src/lib/outcome.ts` reads it, and the miners, the team page and the broken digest walk the one mined margin, 10), `scope=active` (default is all-time), `week=1`, `run`, `t`, `vs`. The view's state and its rules (a new definition resets the column limit, all-time drops the week filter) are the reducer in `src/lib/view.ts`. The analytics embed counts each write as a pageview.
- Code layout: `src/lib` is TypeScript (`npm run typecheck`); components are still JSX. `createModel(payload)` in `createModel.ts` decodes a payload into per-team game rows and evaluates definitions; `model.ts` builds the app's one model from `src/data/payload.json`. The chip catalog is `chips.ts` and reads only row fields. A team's crowns are mined in `crowns.ts` and ranked in `crownRank.ts`: a score in bits past what chance would produce, with the weights in `RANK`. `team.ts` is what a team page and a matchup read: season record, next game, and every team's current streak under each single condition with its rank in the field (one pass over the miner's bitmasks), ordered like the King-of list, by the crown score; the team page shows this list in place of a King-of list. `npm run tuner` writes `data/build/crown-tuner.html`, a page for trying other weights on 20 teams' crowns. `schema.ts` holds the payload's sentinels and flag bits, and the build scripts import it directly (Node strips the types). Tests are Vitest (`npm test`), next to the code.
- Analytics: `track()` in `src/lib/analytics.ts` wraps `window.dhAnalytics?.track(name, props)`, optional-chained because the embed is third-party and blockable. Events: definition, team open, team page, matchup, games, show more, share, save/unsave/apply saved streak, lead apply, leads scope, leads dir, week filter, kofi (`from`: notes or footer).
- A scheduled game is one no build has recorded a result for. It stays a team's next game past its date until the weekly rebuild writes the outcome (the payload is built once a week in season, so a Saturday game is unknown until then, not gone). A scheduled game's line (`upcoming.sp`, from the same CFBD `/lines` call as the season's closing lines) is the line as of the build. It is shown on the next-game row, the team page and the matchup; no chip reads it, because it moves until kickoff.
- Hover interactions use `onPointer*` events, not `onMouse*`, so they work on touch.
- Team marks are committed under `public/logos/` (one-color, result squares) and `public/logos-color/` (column heads, next-game chips, the ledger), one pair per ESPN id, fetched by `scripts/gen-logos.mjs`. `build-current.mjs` nulls the ESPN id of a team whose marks aren't committed (the chip shows its initial) and lists it in `data/build/logo-wants.json`; run `gen-logos`, then `build-current` again, when it reports new opponents. Color marks use ESPN's dark-background variant when it measurably reads better on the page (rule and the by-eye exceptions are in `gen-logos.mjs`); delete a file to refetch it.
- Favicon and OG images are generated by `npm run gen:favicon` and `npm run gen:og` on a developer machine and committed. CI does not regenerate them. `gen:og` writes `public/og.png`, `public/card.png`, 136 team cards under `public/og/team/`, and one card per completed week under `public/og/week/` (that week's broken streaks), drawing from the payload, so re-run it after a redesign, after any grid rule change (it mirrors the column layout, including the reserved top slot on a live run), and whenever a fresher board is worth committing. `npm run gen:og -- --weeks` renders just the week cards — a week's digest is final once the week is, so run it (against a fresh payload) and commit after each weekly rebuild. Text is drawn as opentype.js glyph outlines: sharp's librsvg ignores `FONTCONFIG_FILE`, and opentype.js 2.x emits NaN path data, so it is pinned to 1.3.4.
- Social previews: drewhoover.com's DNS is on Cloudflare (origin stays GitHub Pages, SSL Full (strict)), and the share worker (`workers/share/`, name `streak-king-share`) sits on `drewhoover.com/cfb-streak-king/*`. It rewrites `<head>` for definition boards and matchups — words from `src/lib/shareWords.ts` (pure; its tests pin it to definition.ts) plus `dist/share/meta.json` — and draws each definition's board as a PNG at `/cfb-streak-king/share/og.png?c=…` (workers-og; fonts committed beside the worker, the serif a static instance because satori can't parse variable fonts; data from `dist/share/payload.json`, raw-GitHub fallback). Origin data fetches are edge-cached with a UTC-date cache key so a pre-deploy 404 dies the same day. Deploy with `npx wrangler deploy -c workers/share/wrangler.jsonc` (wrangler is OAuth-logged-in on the dev machine); anything the worker can't word passes through untouched, so the site never depends on it.
- Dev server: `npm run dev`. If port 5173 is busy, `npm run dev -- --port 5174`.
- Worktrees: `data/raw/` and `data/build/` live only in the main checkout. Symlink both into the worktree to run the pipeline, and never `git add -A` there, because the symlinks are not covered by the `.gitignore` directory patterns.
- The window starts at `FIRST_SEASON` in `scripts/lib/window.mjs` (1936). Before 1978 Howell's pages are the only game source; `fbs-span-bridges.json` and `extra-games.json` hold the researched wartime seasons, each row with a source and quote.
- `data/ref/unplayed-postseasons.json` rules on team-seasons that ended without a postseason game and why (a declined bid, a school's no-bowl policy, a conference rule, a ban), each row with receipts (url + verbatim quote). `src/lib/unplayed.ts` joins the rows to the winning runs that lived through them, in two classes: the team's own call (`chose`) and a rule it was under (`ruled`); the Method notes list each class and a streak's panel notes it under the ledger. `node scripts/data/check-receipts.mjs data/ref/unplayed-postseasons.json` string-matches every quote against its page (cached under `data/build/receipt-pages/`); run it after editing the file. Two `played` rows record bowl games the payload's postseason flag missed (Maryland's 1977 Hall of Fame Classic, Florida's 2006 title game); `build-payload.mjs` now flags those, and every January game, so they clear on the next rebuild.
- Data rulings live in `data/ref/` and are applied at build time with fail-loud checks: `repole-errata.json` (parse-repole fails on an entry that matches no row), `coach-overrides.json` (build-payload must report 0 unresolved coach seasons), `alt-home.json`. The "vs [mascots]" and "vs [color] schools" chips read `team-traits.json`, generated by `scripts/data/gen-team-traits.mjs` from CFBD's team list ruled by `mascot-classes.json` (every nickname's name-group and classes; a name-group ships only with 2+ current-FBS teams, so there is no "vs Horned Frogs") and `color-overrides.json` (one identity color per school where the hex-hue rule gets it wrong: Auburn is orange, Purdue is gold). Re-run the generator after editing a ruling; build-current attaches the traits, so CI needs no extra call. After changing the errata, run `scripts/data/export-errata.mjs` against a checkout of `DrewHoo/repole-errata` and push it; that repo is the public CC0 copy.
- The `dataviz-pages-site` skill covers everything else: build-time data, researched datasets, mobile, dates, SEO, registering the project card on the index site.
